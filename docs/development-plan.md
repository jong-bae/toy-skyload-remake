# SkyRoads 리메이크 개발 계획서

> 작성일 2026-10-16 · 상태 초안 v1

## 1. 개요

1993년 Bluemoon Interactive의 DOS 게임 **SkyRoads**를 원작의 손맛은 살리고 현대적인 그래픽과 연출로 **웹 기술 기반으로 새로 만드는** 비공식 팬 리메이크 프로젝트다.

- 1차 목표는 브라우저에서 동작하는 웹 버전을 완성하는 것이다.
- 2차 목표는 Tauri로 Windows `.exe`를 만들고 GitHub Actions로 누구나 내려받아 바로 실행할 수 있게 배포하는 것이다.

## 2. 개발 원칙 (반드시 준수)

### 2.1 클린룸 구현

- **원작 실행 파일(`SKYROADS.EXE`)은 디스어셈블, 디컴파일, 디버깅 등 어떤 방식으로도 분석하지 않는다.**
  - 근거는 `original_file/readme.txt`의 배포 조건 "as long as you don't reverse engineer, and/or modify this program or any of its accompanying files"이다.
- **원작 코드의 로직을 옮기지 않는다.** 모든 코드는 관찰된 동작과 이 문서의 규칙·수치만 보고 새로 설계한다.
- 수치는 **원작을 플레이하며 외부에서 측정(블랙박스 측정)** 해서 얻는다.

### 2.2 에셋과 배포

- 원작 파일(`.LZS`, `.SND`, `.DAT`, `.EXE`)은 **저장소와 배포물에 포함하지 않는다.**
- 그래픽, 사운드, 맵은 자체 제작 에셋을 기본으로 한다.
- 원작 스테이지 지원은 선택 기능으로 둔다. 사용자가 공식 배포본을 직접 내려받아 폴더를 지정하면 런타임에 **읽기만** 한다. 파일 구조는 커뮤니티 공개 문서를 참고한다. 이 기능의 포함 여부는 M7에서 다시 판단한다. (context-notes D-04 참조)
- 프로젝트 이름은 자체 이름을 쓰고 "Inspired by SkyRoads (Bluemoon Interactive, 1993)"와 "비공식 팬 프로젝트"를 명시한다.

## 3. 원작 게임 요소 정리

`SKYROADS.DOC`, 게임 내 HELP 화면, 플레이 관찰을 기준으로 정리한다. 세부 값은 M1 측정에서 채운다.

| 요소 | 내용 |
|---|---|
| 조작 | 좌우 방향키로 좌우 이동, 위/아래로 가속/감속, 스페이스로 점프 |
| 진행 | 격자 형태 도로를 앞으로 달려 끝 지점에 도달하면 클리어 |
| 중력 | 스테이지마다 다르다. 게이지(gravometer)로 점프 가능 정도를 표시 |
| 자원 | 연료(Fuel)와 산소(Oxygen). 하나라도 바닥나면 실패 |
| 실패 조건 | 도로 밖으로 추락, 장애물 정면 충돌, 위험 블록, 연료/산소 고갈 |
| 블록 색상 효과 | 가속, 감속, 미끄러움, 연료·산소 보충, 파괴(즉사) 등 (HELP 화면 기준으로 확정) |
| 지형 | 평평한 타일, 높이가 다른 블록, 터널 |
| 스테이지 | 여러 월드(배경 테마)에 걸친 다수 스테이지 |

## 4. 수치 데이터 확보 계획 (블랙박스 측정)

### 4.1 측정 환경

- `dosplay/` 폴더의 DOSBox 환경에서 원작을 실행한다. (`dosplay/run.bat`)
- 측정마다 DOSBox `cycles` 값을 고정하고 그 값을 기록한다. (속도 의존성 제거)
- DOSBox 영상 녹화 기능(Ctrl+Alt+F5)으로 플레이를 녹화한다.
- 녹화본을 `ffmpeg`로 프레임 단위 이미지로 나누고, 프레임 번호와 화면상 위치로 시간과 거리를 계산한다.
- 거리 단위는 **타일 1칸**, 시간 단위는 **초**로 통일한다.

### 4.2 측정 항목

| ID | 항목 | 측정 방법 | 산출 값 |
|---|---|---|---|
| M-01 | 전진 최고 속도 | 직선 구간을 최고 속도로 달리며 타일 통과 프레임 수 계산 | 타일/초 |
| M-02 | 가속·감속 곡선 | 정지 → 최고 속도, 최고 속도 → 정지까지 걸린 시간과 중간 속도 | 시간-속도 표 |
| M-03 | 속도 단계 | 계기판 속도 표시가 몇 단계로 바뀌는지 | 단계 수 |
| M-04 | 좌우 이동 속도 | 가로로 1칸, 전체 폭 이동에 걸린 시간 | 타일/초, 관성 유무 |
| M-05 | 점프 높이·체공 시간 | 중력별 대표 스테이지에서 평지 점프 녹화, 최고점 높이와 착지까지 프레임 | 중력별 높이·시간 |
| M-06 | 점프 거리 | 최고 속도와 중간 속도에서 점프해 넘을 수 있는 칸 수 | 속도별 칸 수 |
| M-07 | 낙하 | 도로 밖으로 떨어질 때 실패 판정까지 시간, 낮은 블록으로 떨어질 때 생존 여부 | 판정 규칙 |
| M-08 | 정면 충돌 | 블록 정면에 속도별로 부딪쳐 폭발하는 경계 속도 | 규칙, 경계 속도 |
| M-09 | 측면 충돌 | 블록 측면에 닿았을 때 반응 (막힘, 튕김, 폭발) | 규칙 |
| M-10 | 착지 판정 | 블록 모서리 걸침, 높은 블록 위 착지 허용 범위 | 허용 오차 |
| M-11 | 연료 소모 | 일정 속도에서 시간에 따른 게이지 감소, 속도 의존성 | 소모율 |
| M-12 | 산소 소모 | 시간에 따른 게이지 감소 | 소모율 |
| M-13 | 블록 효과 | 색상별 블록을 하나씩 밟고 속도·조작·자원 변화 관찰 | 블록 효과 표 |
| M-14 | 터널 | 터널 안 점프 제한, 천장 충돌 | 규칙 |
| M-15 | 카메라 | 시야각, 카메라 높이, 화면에 보이는 앞쪽 칸 수 | 연출 기준값 |
| M-16 | 데모 플레이 | 원작 데모 모드를 녹화해 비교용 참고 영상으로 보관 | 영상 |

### 4.3 측정 산출물

- `docs/measurements.md`에 항목별 **측정값, 측정 횟수, 오차, 신뢰도(상/중/하)** 를 기록한다.
- 측정값은 그대로 쓰지 않고 `src/core/config.ts`의 **튜닝 상수**로 옮긴 뒤, 원작 녹화와 나란히 비교하며 보정한다.
- 원본 녹화 영상과 프레임 이미지는 용량과 저작권 문제로 저장소에 넣지 않는다.

## 6. 아키텍처

### 6.1 핵심 설계

- **시뮬레이션과 렌더링 분리.** 게임 로직은 고정 시간 간격(fixed timestep)으로 돌고, 렌더링은 모니터 주사율에 맞춰 보간한다. 원작 손맛은 시뮬레이션에서 결정되므로 기기 성능과 무관하게 같은 결과가 나와야 한다.
- **결정론적 코어.** 같은 맵과 같은 입력 기록이면 항상 같은 결과가 나온다. 이를 이용해 입력 리플레이 기반 회귀 테스트를 만든다.
- **자체 맵 포맷(JSON).** 맵은 우리가 정의한 JSON 구조로 표현한다. 원작 데이터 지원을 넣더라도 이 포맷으로 변환해서 쓴다.

### 6.2 폴더 구조 (예정)

```
skyload/
├─ docs/                  계획서, 체크리스트, 측정 기록
├─ src/
│  ├─ core/               순수 TS 게임 로직 (렌더링·DOM 의존 없음)
│  │  ├─ config.ts        튜닝 상수 (측정값 기반)
│  │  ├─ physics.ts       이동, 점프, 중력
│  │  ├─ collision.ts     충돌, 착지, 추락 판정
│  │  ├─ blocks.ts        블록 효과
│  │  └─ simulation.ts    고정 스텝 루프, 상태
│  ├─ level/              맵 포맷 정의, 로더
│  ├─ render/             Three.js 씬, 카메라, 이펙트
│  ├─ input/              키보드, 게임패드
│  ├─ audio/              효과음, 음악
│  └─ ui/                 메뉴, HUD
├─ levels/                자체 제작 맵 (JSON)
├─ tests/                 코어 단위 테스트, 리플레이 테스트
└─ src-tauri/             (2차) 데스크톱 패키징
```

### 6.3 맵 데이터 모델 (초안)

- 도로는 가로 7칸 × 세로 N줄 격자로 본다. (가로 칸 수는 M1에서 확인)
- 각 칸은 바닥 타일 유무와 색상, 그 위 블록 유무와 높이, 터널 여부를 가진다.
- 스테이지 단위 속성은 중력, 연료량, 산소량, 월드(배경) 번호다.

| **M4** 게임 규칙 | 블록 효과, 연료·산소, 터널, 클리어·실패 흐름 | 블록 효과 전부 동작, 원작 녹화와 체감 비교 통과 |

| **M6** 현대화 | 조명, 네온, 파티클, 화면 흔들림, 배경 연출, 새 음악 | 60fps 유지 (중급 노트북 기준) |
| **M7** 원작 데이터 (선택) | 사용자 지정 폴더의 원작 맵 읽기 기능 여부 판단 후 구현 | 판단 결과를 context-notes에 기록 |
| **P2-1** 데스크톱 | Tauri로 감싸 Windows exe 빌드 | 설치 없이 또는 설치 후 바로 실행 |
| **P2-2** 배포 | GitHub Actions 태그 릴리스 자동화 | `v*` 태그 푸시 시 Release에 exe 첨부 |

## 8. 테스트 전략

- **코어 단위 테스트.** 점프 높이, 체공 시간, 최고 속도 등을 측정값과 비교한다.
- **리플레이 테스트.** 입력 기록 파일을 재생해 같은 지점에서 클리어 또는 실패하는지 확인한다. 물리 상수를 바꿨을 때 회귀를 잡는다.
- **체감 비교.** 원작 녹화와 리메이크 녹화를 나란히 놓고 같은 구간을 비교한다. 수치로 잡히지 않는 손맛은 여기서 조정한다.

## 9. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| 블랙박스 측정의 정밀도 한계 | 손맛이 미묘하게 다름 | 측정 반복, 체감 비교로 튜닝. 완벽한 1:1이 아니라 "원작 느낌"을 목표로 함 |
| DOSBox 속도에 따른 측정값 변동 | 수치 불일치 | `cycles` 고정, 설정값 기록 |
| 원작 맵 지원의 법적 모호성 | 배포 리스크 | 기본은 자체 맵. 원작 맵 기능은 M7에서 별도 판단 |
| 3D 전환 시 원작의 2.5D 감각 손실 | 느낌이 달라짐 | 카메라 각도·시야를 원작 측정값(M-15)에 맞춘 "클래식 카메라" 옵션 제공 |
| 범위 확장 | 일정 지연 | M5까지를 최소 완성 범위로 고정, M6 이후는 추가 작업 |
